# Flirra MySQL migration — Phase 2 baseline

This branch contains a separate MySQL Prisma schema and a fresh baseline migration. The original PostgreSQL schema and `prisma/migrations/` directory are unchanged.

## Artifacts

- `prisma/schema.mysql.prisma` — MySQL provider schema for all existing models.
- `prisma/migrations_mysql/00000000000000_mysql_baseline/migration.sql` — generated from the MySQL schema with `prisma migrate diff --from-empty`.

The PostgreSQL schema remains the runtime schema until the conversion is fully tested against a disposable MySQL database. Do not point production at this baseline yet.

## Schema conversions

- PostgreSQL `String[]` fields (`UserProfile.interests` and `SupportFAQ.keywords`) are represented as JSON arrays in the MySQL schema. Application validators must continue to enforce string-array shape.
- PostgreSQL `JSONB` fields are represented as Prisma `Json`/MySQL JSON columns.
- Prisma enums remain explicit MySQL `ENUM` columns in the generated migration.
- Monetary and wallet values remain integer minor-unit/coin fields as in the source schema; no floating point conversion is introduced.
- Foreign keys, unique constraints, and indexes are generated by Prisma and must be checked against the imported data before cutover.

## Commands (disposable database only)

```sh
DATABASE_URL='mysql://USER:PASSWORD@127.0.0.1:3306/flirra_migration_test' \
  npx prisma validate --schema prisma/schema.mysql.prisma

DATABASE_URL='mysql://USER:PASSWORD@127.0.0.1:3306/flirra_migration_test' \
  npx prisma db execute --schema prisma/schema.mysql.prisma \
  --file prisma/migrations_mysql/00000000000000_mysql_baseline/migration.sql

DATABASE_URL='mysql://USER:PASSWORD@127.0.0.1:3306/flirra_migration_test' \
  npx prisma generate --schema prisma/schema.mysql.prisma
```

These commands have not been run against production. A logical backup and a disposable import are required before any cutover.

## Blocking work before cutover

1. Rewrite PostgreSQL raw SQL in billing, calls, rewards, gifts, support, and admin analytics. MySQL does not support PostgreSQL casts, `date_trunc`, `RETURNING`, or quoted identifiers in the current form.
2. Add and test a persistent MySQL rate-limit table with atomic update/insert semantics. Process-local memory is not acceptable.
3. Replace Redis-backed matchmaking, locks, presence, counters, and Socket.IO adapter coordination with supported shared storage or an approved external real-time transport.
4. Import and verify users, wallets, payments, transactions, messages, gifts, earnings, and relationships by record counts and balance totals.
5. Switch the runtime schema only after integration tests pass against the disposable MySQL database.

No production data was modified by this phase.
